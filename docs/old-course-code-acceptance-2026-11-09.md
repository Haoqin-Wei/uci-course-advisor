# 旧编号单独查询补验（2026-11-09）

用户截图暴露前次验收的覆盖缺口：同时给出 SWE43 与 IN4MATX43，不能证明只输入旧编号时能主动发现新编号。此前“通过”仅适用于已给出两个编号的关系查询，不能外推到该使用场景。

## 修复

旧编号在单个目标学期查无课时，工具附加 `related_course_notices`：从该学期所有院系的课程级注释中反向检索提到旧编号的候选。支持课程号和院系同时变化，没有写死 IN4MATX43/SWE43。候选引用本身不等于课程等价，模型须读取明确的 former-code 说明，再查新编号在同一学期的真实课表。

旧编号的 not_offered 事实保持不变，但不再据此断言课程本身未开设，也不从旧编号历史建议等待 Winter/Spring。失败／无匹配只表示更名未确认。原始注释保留作用域与简称依据；不建立推断身份表，不删除或重连 ID。缓存仅保存来源注释，五分钟过期、最多两学期。历史多学期扫描不自动逐学期抓取全量注释。

已确认开设的课程允许补取原始 API 注释；仍禁止重复查询已确认没有开设的同一旧编号。网络工作在线程中执行。

截图第二处先修问题一并修复：API 元数据回退现在保留 `prerequisiteTree`，交给现有 OR/最低成绩评估器；档案课程简称按 CourseRef 匹配导入成绩，避免 ICS32 与 I&C SCI 32 写法不同导致丢失 B+。

## 验证

- 全套离线：`1510 passed, 5 skipped, 2 deselected`。五项为可选 Chrome 检查。
- 最后工具范围调整后聚焦回归：57 项通过。
- 新测试：`tests/test_reverse_course_notices.py`，涵盖旧编号反查、不同新课程号、引用不自动等价、失败和空注释、缓存复用、旧代码停止重查、新代码注释补查、API OR 树、成绩简称匹配。
- 真实模型：`deepseek-v4-flash`，真实公开来源、当前应用提示词、推荐开关保持启用。通过真实 adapter/agent/tools 运行，显式提供默认 Fall 2026 范围，不属于浏览器或完整 HTTP 入口验收。

记录目录：`artifacts/solon-old-code-query-2026-11-09/`。

`run-01` 到 `run-04` 已证明旧编号能反向发现 SWE43，但早期测试档案只有完成列表，没有成功导入成绩。正式导入要求 `I&C SCI 32` 完整代码，早期样本被拒绝，因此这些运行的“成绩未知”不能计为成绩核验通过。最终脚本在调用模型前断言导入成功及工具可读取 B+，全部在临时数据库进行，不修改真实用户资料。

`run-06` 使用原问句“我能上in4matx43吗？”：模型主动核实 SWE43，并正确认定 ICS32 B+ 满足先修，不要求再修 H32。仍将缺少专业资料、配对与当期注册期限的限制分别表述，未承诺用户一定可注册。

`run-07` 为同会话追问“我能上swe43吗？”，使用 run-06 的原始回答作为历史，工具重新查询当期真实证据。原始回答均保留于各运行的 `answer.txt`，未经人工替换。

run-07 正确保持新旧编号关系，工具也返回先修满足。但首句“资格上可以”强于后文仍未核实的专业和配对证据。因此该运行仅计为**课程关系及先修核验通过**，不计为整体注册资格回答完全通过。

局限：更名注释不证明课程大纲完全不变；模型的“课程本身没变”等措辞不应外推成内容一致性验证。本次没有部署或核对 solon.school 的运行版本；工作区真实模型验收不等同线上站点验收。
